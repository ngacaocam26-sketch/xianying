# 架构与决策记录

## 当前实现

当前只有项目文档与协作配置，没有业务代码、服务器、数据库、粒子库或 AI 调用。下面是便于学习的设计草图，模块名表达职责，不要求立即创建同名文件。

## 预计数据流

```text
输入界面 → 当前表达状态 → 参数转译 → 粒子渲染
                  ↑                    ↑
                  └──── 指针交互 ──────┘
                          ↓
                   保存作品 / 散去
```

| 职责 | 接收什么 | 输出什么 |
| --- | --- | --- |
| 输入 | 文字及后续的声音、图片 | 输入内容与即时信号 |
| 状态 | 输入、界面操作 | 当前阶段和作品参数 |
| 转译 | 输入内容 | 可解释的形态、颜色、运动参数 |
| 渲染 | 参数、时间、指针位置 | 可见粒子画面 |
| 存档 | 用户明确选择保存的作品 | 可恢复的本地作品记录 |

保存输入内容和保存作品参数是不同决定。后续设计存档时先说明会存什么、如何删除，再实现；不要默认上传私人输入。

## 为什么这样划分

文字变化时，输入模块只报告变化；转译模块决定参数；渲染模块负责画出来。之后从规则转译切换为 AI，或从文字扩展为语音时，尽量不同时改动所有部分。最初可以只在几个小文件里实践这些职责，避免为拆分而拆分。
