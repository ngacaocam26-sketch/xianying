### 渲染与交互数据流

```text
React 挂载 → Effect 创建 Three.js 场景、相机、预分配数组与 GPU 资源
非闭合弧面 u/v 采样 → 偏心内腔、上下回卷唇边与细波纹 → 沿法线增加厚度与少量浮尘
造型坐标 + 折脊方向 → 内褶暖光、冰蓝/银灰外层与暗谷；曲面边缘渐隐
逐点颜色/大小/透明度/柔光标记 → ShaderMaterial：约 95% 解析亮核 + 5% 径向渐变柔光
动画时间 → 局部呼吸开合与整体小幅侧摆 → 更新物体矩阵
指针/触屏 → 局部射线 → 前层深度选择与局部作用范围 → 位移/速度 → dt 子步弹簧阻尼
更新预分配数据 → THREE.Points 发光叠加 → 透明画布与 CSS 暗房背景合成
```

粒子材质使用 AdditiveBlending、transparent 与 depthWrite: false。为避免整团模糊，约 95% 的点使用解析圆形亮核，仅圆周用 fwidth 抗锯齿；约 5% 的点使用原 64 × 64 径向渐变纹理提供低强度柔光，通过 aGlow 属性在同一个 Points / draw call 内完成。点径下限随 DPR 换算，并按放大面积补偿透明度，避免远处小点被放大成亮团。褶皱光纱保留这套材质，增加相对物体中心的深度明暗提示：后层仍清晰但略暗，不使用景深模糊，也不把透明点误写入深度缓冲。没有增加 Bloom 后处理或依赖。

形体使用围绕偏心内腔的非闭合弧面，弧长、宽度、上下唇边回卷决定不对称轮廓；细波纹与沿法线的厚度补充局部体积。颜色、边缘淡出由未折叠的 u/v 坐标和折脊方向决定，因此增加 Z 深度不会把内层误判成远端边缘。暖光分布在两处内褶，不再把所有粒子与高光集中于同一中心。

React 不管理逐帧坐标。交互位移和速度保存在场景内部的预分配数组；时间步长受限并分子步积分，减少帧间隔变化对回弹的影响。拾取通过预分配深度分箱寻找有邻点支持的前层，忽略极低透明度与柔光点；使用原位避免手势拨开的孔导致不断选中后层。按下锁定局部深度平面，悬停明显移动才重选，作用限制在这一层附近；释放、取消和失焦清锁。整体侧摆先更新矩阵，再把指针射线转换到局部空间。当前主指针由 pointerId 管理，避免鼠标与触摸同时输入时互相抢占。OrbitControls 已移除：拖动用于拨动局部粒子，不控制相机旋转或缩放。

窗口尺寸变化时同步画布与相机。页面隐藏时停止动画调度；减少动态效果偏好关闭环境运动，保留主动交互。Effect 清理动画、监听、观察器及几何体、材质、纹理和渲染器资源；不把清理代码的存在等同于长期内存测试通过。

### 照片数据流（2026-10-26 起：浮雕画法）

```text
相机按钮 → 本地 File → preparePhotoAttachment 校验、按 EXIF 方向解码、缩到最长边 768 并重编码 JPEG

指针 → 局部平面 uv → 压痕场（模糊 + 衰减 + 圆形压痕取最大）→ 粒子推到孔沿外并提亮
```

### 旧版照片数据流（T01-B2 / B3，仅旧存档）

```text
投射 → 本地 File → photoToParticles 解码/缩小 → Canvas 读取 RGBA
像素位置 + 确定性抖动 → x/y；亮度 + 曲面 + 厚度噪声 → z
sRGB → 线性 RGB；亮度/边缘/源 alpha → 逐点大小、透明度、流动幅度
PhotoParticleData → App 状态 → ParticleScene → BufferGeometry / THREE.Points
顶点着色器 → 主体低幅度流动 / 外围散开；物体轻微侧摆 → 视差
```

照片的粒子转换只在本地处理，模型缩略图另见后文。点云采样长边最多 360、采样点不超过 64,000，以原始宽高比生成；拒绝空文件、超过 20 MB、超过 4000 万像素、损坏图片和全透明图片。解码得到的 ImageBitmap 在 finally 中关闭。B2 使用加法叠光，缩小点径并控制透明度避免过曝；少量柔光点补充光尘感。原色是起点，叠光和外围消隐会改变最终外观，不宣称原色精确再现或真实三维重建。

PhotoParticleData 由统一 pointSize 改为逐点 sizes、phases、flows、glows。照片环境流动继续由 GPU 计算；B3 新增独立 aDisplacement，与原位流动相加。CPU 仅在主动手势或尚有残余位移/速度时更新。笔刷经相机射线与照片局部 z=0 平面相交，沿实际事件之间的线段影响附近粒子；这是浅浮雕的近似映射，不是任意三维模型的表面拾取。命中使用与 shader 一致的 x/y 原位流场，局部范围之外跳过正弦计算。照片始终保留原始采样数据。

当前手势把真实轨迹转为速度冲量，不直接搬动粒子。固定种子的逐点耦合强度让少量颗粒明显扬起，多数轻微移动；平滑轨迹权重、空间扰动、横向与深度差异打散整齐边界，减少整片粒子挤在同一条亮边。输入按屏幕坐标进入最多 64 项的队列，接收合并事件，一帧内反向与释放前的移动仍可处理；溢出时保留最终位置。前后坐标用同一物体矩阵投影，避免侧摆被当作鼠标运动。离开/重新进入、尺寸变化时断开旧轨迹，静止无冲量。

停止输入后保留速度，以逐点频率 0.82–1.20 的临界阻尼解析解推进位移和速度：先短暂续行，再缓慢收拢，无弹簧往返振荡。速度按逐点强度设上限，过大位移连续增强归位力度，避免统一半径的硬截断；单步时间限制为 50 ms（渲染层为 40 ms）。某分量的位移和速度都低于 1e-5 才清零。页面隐藏暂停；减少动态效果时仅主动互动和恢复期间调度照片动画，静止后停帧。主指针捕获、取消、离开与失焦路径共用，照片跳过默认雕塑的深度选层。监听随场景清理。默认雕塑 aFlow 为零，形体和原物理分支保留。

App 的请求序号防止旧解码结果覆盖新选择或返回暗房。失败保留上一幅画面，可重复选择同一文件。photo 引用变化时 Effect 先清理旧资源再创建新场景；普通提示和视觉参数变化不重建场景。聊天打开时给画面留空间；窄屏照片在上、对话在下。THE DARKROOM 清空照片、恢复中性参数并收起对话。原图与点云只在本地，模型仅在主动发送后看到重编码的 JPEG 缩略图；无相机采集或自动存档。

## 文字/照片对话与视觉联动（2026-10-20）

```text
书写 → ChatPanel 内存中保存草稿/对话 → 用户主动发送
最近 5 轮完整对话 + 当前输入 + 当前 JPEG 缩略图 + 当前作品参数 → POST /api/chat
Vite 同源代理 → Node 校验 → system prompt + 上下文/当前图片 → qwen3.8-flash
JSON Schema 流式输出 {reply,visual} → 服务端只抽取 reply → NDJSON delta → 面板显示
完整 stop + JSON 解析 → 校验视觉参数 → done → 前端再次校验 → App 更新目标
场景 ref + 指数平滑 → 扩展比例 / 时间速率 / 色温 uniform → Three.js 渐变
停止/收起/返回暗房/清空 → AbortController → 取消后端与模型请求
```

`.env` 只由 Node 入口加载，字段为 DASHSCOPE_API_KEY、QWEN_MODEL、可选 DASHSCOPE_WORKSPACE_ID；不进入 VITE_ 环境或前端包。空业务空间 ID 使用官方北京 DashScope 兼容域名，填写后使用专属域名。`GET /api/status` 只反映是否有配置，不探测密钥有效性。

输入最多 2000 字、11 条交替消息、24000 字上下文，整个请求上限 448 KiB；不接受客户端 system 角色。图片仅接受长度 320000 字符内的 JPEG data URL，检查 Base64、JPEG 起始签名及 1—768 的声明尺寸；不代替完整图像解码，不接受远程图片 URL。浏览器通过 Canvas 缩小并重新编码，去除原图元数据。后端 45 秒超时、900 tokens 生成上限、完整 JSON 最多 16000 字符/回复最多 4000 字、2 并发、每分钟 20 次。无跨站 CORS，只监听回环地址；公开部署仍需访问控制。错误不透传服务商原始内容或记录私人数据。

只有完整成功轮次进入上下文；每轮仅在当前 user 消息附一张当前缩略图，历史保留自然文本。换照片通过 keyed ChatPanel 重建当前会话、取消旧请求，并恢复中性视觉参数；解码失败保留当前照片/会话。停止/失败片段标为未完成，不应用参数；参数缺失/类型错误时保留回复与画面并提示。数字字段只接受有限 number，限制到 0—1；不会执行模型代码。流式 JSON 引号、转义和 Unicode 分片单独处理，不将 JSON 结构呈现给用户。

VisualState 包含 dispersion/motion/warmth，中性均为 0.5。每帧在场景内按指数平滑接近目标，整体尺度 0.8—1.2、环境时钟速率 0.35—1.65、红蓝倍率 0.78—1.22；不改写照片原始采样或手势物理。视觉目标变化只更新 ref/唤醒渲染，不重建 GPU 资源。减少动态效果时直接应用目标并按需绘制，页面隐藏仍暂停；这些设备偏好路径尚未完成真实设备验收。Node 24 直接加载纯参数 TypeScript，tsconfig 允许 .ts 扩展并保持 noEmit。

聊天/照片只在内存，不落盘；`build` 只生成前端，生产后端与线上部署尚未创建。

## 已确认的后续方向（部分已实现）

用户明确希望文字、语音和 AI 交流逐步形成情绪雕塑，照片先保留内容并粒子化。后续按国内模型视觉转译、实时语音及存档逐项推进，不预建完整框架、通用状态库或账户系统。

```text
照片 → 本地降采样 → 位置/颜色/亮度 → Three.js 立即预览
文字/缩略图/语音 → 用户主动提交 → Node API → 对应的百炼模型
AI 结构化参数 → visual.ts 校验与限制（已实现） → Three.js 平滑改变形态
指针 → Three.js 局部形变与回弹
凝结 → 固定作品数据/参数/种子 → 用户选择保存或散去
保存 → IndexedDB 本地作品；localStorage 只保存轻量偏好
```

| 模块 | 后续职责与边界 |
| --- | --- |
| React | 输入方式、表达内容、体验阶段与作品状态，不管理逐帧粒子坐标 |

| 本地存档（已实现基本流程） | IndexedDB 保存恢复作品所需的数据、参数、相位、种子及预览，明确操作才写入；未实现云同步或导出迁移 |

照片先在本地预览，用户主动显影后才发送转译请求。AI 转译需要联网；等待或失败时保留可互动的本地画面。相机、麦克风、缩略图及录音传输在对应功能实现时再处理权限与说明。

仅存参数无法恢复照片内容，因此原 localStorage 作品快照计划已被 IndexedDB 方案替代。保存必须明确触发，不保存原始文字、录音或完整照片；本轮 v1 快照见下。

## 凝结与本地存档（2026-10-21）

ParticleScene 暴露 capture 句柄：取得正在显示的平滑作品参数和环境相位，固定 NEBULA_SEED；照片克隆 positions/colors/alphas/sizes/phases/flows/glows 及取景尺寸。JPEG 预览先同步 render，再复制到 320×220 Canvas，避免默认 WebGL framebuffer 已清空。预览只包含粒子画面，名称由用户另行输入。

App 建立版本 1 Artwork（UUID、名称、时间、预览、SceneSnapshot）。凝结会停止文字生成/实时收音，锁定环境相位与作品参数；临时位移/速度不存档，原手势与归位仍可用。每次凝结新 UUID，保存同 ID 幂等，不覆盖现有作品；继续表达再凝结生成新作。回廊开合暂停/恢复场景，恢复时重新取景，避免背景渲染及窄屏切换后位置错误。

IndexedDB `xianying-local-gallery` v1 分 `works`（完整作品）和 `cards`（小型列表元数据，不含粒子数组）。保存必须同一 readwrite transaction 两份写入并等待 complete 才返回成功；第二份失败会回滚第一份。列表只读 cards，打开单件才读完整 works。操作后关闭连接，版本变化也关闭；blocked/5 秒打开等待、禁用存储、QuotaExceeded、事务中断返回说明并保留当前作品。校验版本、有限数组值、长度/采样上限、JPEG data URL 与名称，投影允许字段后才写入；未知版本或损坏场景不进渲染、不覆盖记录。

回廊移除仅设置 cards.removedAt，跨刷新保留，可从「已移除」恢复；不提供不可撤销的批量清空，移除不立即释放空间。散去仅以短暂淡出结束当前场景，取消请求/收音、清空当前照片与对话、回到默认暗房；不调用保存或移除。正在保存时阻止重复操作/切换，未保存凝结在回廊可浏览但禁止被另一件覆盖。异步请求和卸载使用序号/存活状态防止旧结果回写。

存档按浏览器/Origin 隔离，含端口；没有跨设备/域名迁移或导出，清理站点数据会丢失。恢复照片时没有 AI 上传附件和原图，作品仍可互动；继续表达需要 AI 看图时重新投射。复用 v1 算法/种子恢复默认雕塑，未来改变形体/着色器算法需评估版本兼容，不能默认为旧作完全相同。

## 实时语音数据流（2026-10-20）

用户点击开始 → AudioContext 恢复与 getUserMedia → AudioWorklet 将设备采样率转为 16kHz 单声道 PCM16LE → 每 100ms 发往同源 /api/voice → Node ws 附密钥连接北京 Realtime → session.update 配置文字+音频、Tina 音色、服务端 VAD（0.7s 停顿）与输入转写 → 24kHz PCM 音频排队播放、两侧字幕更新。

音频双向由 WebSocket 转发，选择它便于控制播放器的全部排队片段，不需要把长期 Key 交给浏览器。音频包限制 6400 字节、连接内速率/积压校验、连接最长 5 分钟、并发 2 条、握手 15 秒超时与心跳；用户端握手等候 20 秒。错误只返回固定说明，不带提供商原始错误或 Key。公开部署仍需独立访问控制和额度设计。

自然插话依据服务端 speech_started 事件：如仍在生成则 response.cancel，同时本地停止并断开全部已排队 AudioBufferSourceNode。按钮先清空本地队列再请求取消；两端用 response ID 屏蔽旧片段，防止串入下一轮。未采用官方未文档化的 conversation.item.truncate，因此服务保留的语境可能包含用户未听完的内容。已生成的语音不因取消而保证免计费。

麦克风权限晚到、开始期间关闭、连接失败/超时、设备断开、主动结束、面板关闭、切换入口、返回暗房、卸载、pagehide/visibilitychange 共用清理；stop 幂等，释放音轨、节点、播放器、WebSocket 和 AudioContext。对话语境仍与文字/照片独立；2026-10-21 新增语音作品显化，见下。

## 文字/语音表达显化（2026-10-21）

visual 扩展为八项。旧三项外，openness 影响横向展开/深度包裹，tension 影响收紧与褶皱，coherence 在低值时按共享角度分组分离、高值时收拢深度，weight 调整下坠/纵向延展，luminosity 控制受限亮度。writeEmotionRest 由原位数据和连续参数计算静息位置，再叠加原手势/归位；拾取使用变形后的静息位置。全中性时复现旧环境流场，照片不应用大幅结构变形。参数只更新 ref/平滑，逐句不重建场景/GPU。

文字 Chat Completions 仍一次流式返回 reply+visual，八字段 JSON Schema 使用共用 SCULPTURE_GUIDANCE。语音 Realtime 保留听/说/打断，AudioWorklet 的 PCM 包计算 RMS 后通过活动 ref 提供轻微缩放/亮度脉动（减少动态偏好下关闭）；完整 ASR 转写交给 VoiceSculptor → 同源 POST /api/sculpture → 现有 qwen3.8-flash 非流式八字段 JSON，仅基于用户最近 5 句/当前作品，不混入 AI 安慰回复。每句最多 1600 字、总量不超过 8000；350 tokens，前端 15 秒等待，服务端共用输入校验/限流/取消/错误脱敏。每句稳定转写会增加一次文本模型调用。

VoiceSculptor 按语音 item ID 排序保留短上下文；新开口、按钮打断、结束/切换/凝结/卸载会增加序号并 Abort。即使底层请求忽略取消，旧结果也不应用；迟到旧转写可补上下文但不更新画面。失败保留已有作品，可只重试显影，不重放音频、不结束会话。语音和文字历史暂不合并，画面参数状态可延续。

新作品/场景/卡片写 version 2，保存八项参数。读取 v1 保留旧三项，新增维度按中性补齐用于渲染；不重写旧数据，不升级 IndexedDB 表结构。新旧作品都可打开，新版凝结仍保留临时手势归位。未来改变形态算法仍需按版本处理。

布局以作品持续可见为目标：宽屏右侧 360px 对话，1000px 内上下分区，短横屏左右分区；输入时收起原入口胶囊，由面板内凝结/关闭完成阶段切换。声明的 viewport 检查不代替真实键盘/手机。

新增模块时写清职责、输入、输出、运行方法；改变接口或技术选择时新增一条决策。不要提前堆叠尚未实现的架构图或依赖。
