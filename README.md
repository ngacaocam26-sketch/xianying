# 显影：把一次情绪变成可触摸的粒子雕塑

用文字、声音或画面表达此刻，让表达逐渐显形成可以互动的粒子雕塑，并选择留下或让它散去。

## 当前状态

这是一个以学习架构和开发为优先的个人项目。T01-A 暂告一段落，保留默认雕塑与暗房界面。B1 已接通图片选择；用户认为 B2 粒子浮雕初步接近目标。B3 已统一调整为稀疏受力、沿划动方向流散、独立速度惯性与缓慢归位；类型检查、构建和运动回归通过，浏览器验证范围见 DEV_LOG，不等同于用户视觉认可。

采用 Vite + React + TypeScript + Three.js。点击底部输入条左侧的相机选择 JPG、PNG 或 WebP，先在本地生成可拨动的粒子浮雕，输入条随即切换为看图对话。原图留在本机，只有主动发送时，最长边 768 像素的 JPEG 缩略图才随文字交给百炼。可直接发送照片，也可先写一句话；再点相机换照片会开始新对话。THE DARKROOM 或左上角「显影」返回原雕塑。照片和对话不自动保存。

文字及看图交流使用北京地域 `qwen3.8-flash`，一次流式请求返回回复和作品参数，校验后调整疏散、流动与冷暖。语音（输入条右侧麦克风）使用 `qwen3.8-omni-flash-realtime`，独立语音的说/听/打断已用合成音频联调。凝结、命名、IndexedDB 保存、散去和本地回廊已接通；已验证照片作品与真实 AI 参数作品刷新后恢复。物理麦克风/扬声器、情绪回应质量、真实手机与国内不同网络仍待本人验证。

## 运行粒子场景

### VS Code 一键启动与预览

用 VS Code「文件 → 打开文件夹」打开 `D:\显影`。项目已配置 `.vscode/tasks.json`：

- 首次打开时，如果提示是否允许自动任务，选择允许此文件夹的自动任务。若没有出现提示，按 `Ctrl+Shift+P`，执行 `Tasks: Manage Automatic Tasks in Folder`（管理文件夹中的自动任务），选择允许，再重新打开该文件夹。
- 允许后，每次打开项目会同时启动 Vite 与本地 Node API，并在默认浏览器打开实际地址。不要用 Live Server / Go Live 打开源 `index.html`。
- 手动启动按 `Ctrl+Shift+B`，或通过「终端 → 运行任务 → 显影：启动并预览」。这是本项目的默认构建任务快捷键，实际动作是启动预览，不是生产打包。
- 服务已运行时，使用任务终端中显示的 Local 链接重新打开页面；同一任务限制为一个运行实例。其它窗口或终端启动的服务不受此限制。
- 端口占用时 Vite 自动顺延，并打开实际使用的地址，不必记住 5173 或 5175。
- 保存代码后浏览器自动更新。停止时在该任务终端按 `Ctrl+C`，或选择「终端 → 终止任务」。

自动任务仍受 VS Code 的工作区信任与自动任务许可控制；此配置没有修改全局设置。当前作品不会自动保存。以下命令行方式仍可使用。

已在 Node.js 24.14.0、npm 11.9.0 环境验证。从项目根目录运行：

```powershell
npm.cmd ci
npm.cmd run dev
```

依赖已安装时可直接运行第二条命令。打开终端显示的本地地址，默认是 http://127.0.0.1:5173/；开发服务器仅监听本机。停止时在终端按 Ctrl+C。

打开即是默认雕塑：银白单色、由十几万颗粒子组成的光雕，外围一圈淡淡的浮尘；它会缓慢转动，按住鼠标或手指拖动会推开一个透过去的小黑洞，松开后慢慢合上。它有五种形态——凝聚、交织、垂落、舒展、离散，文字和语音给出的作品参数决定它长成哪一种，换形态时粒子约两秒流过去；冷暖、明暗和细微的舒展、下沉也随参数变化。凝结时如有对话，AI 会起一个标题、写一句总结（新增 `/api/title`，改动后需重启开发服务）。回廊中早期保存的星云作品仍以原画法打开。界面按参考视频改为作品居中：顶部小字导航与状态胶囊（显影 · 在听 / 正在回应…），底部一条毛玻璃输入条（相机 / 文字 / 麦克风）和「凝结此刻」，AI 回复以毛玻璃卡片浮在作品上，只显示最近一轮，可「回看」完整记录或「收起」。隐私与数据说明集中在 INFO，输入条下保留一行简短提示。

照片接受不超过 20 MB、4000 万像素的 JPG / PNG / WebP，按拍摄方向缩到最长边 768 并重编码。画面使用与 `/relief-lab` 相同的浮雕画法：桌面约 15 万颗表面粒子（触屏较少），保留照片原色，外缘散开成细尘；鼠标移过或手指按住会推开一个小黑洞，离开后慢慢合上。AI 给出的作品参数改变光感、冷暖、流速和散开程度，照片主体保持可辨认。取消选择或读取失败保留当前画面；这是艺术化浮雕，不是真实三维重建；刷新页面会回到默认暗房。

直接在底部输入条书写；投一张照片后，同一输入条进入看图对话。配置方法见 [API_SETUP](docs/API_SETUP.md)。主动发送时，文字、最近 5 轮完整交流和当前照片缩略图交给百炼；刷新会清空对话，更换照片另开对话。照片只缩小一次并复用，每轮仅发送当前照片。停止、切换语音或返回暗房会取消请求，失败或参数无效时保留已有画面。Google Fonts 不可访问时使用系统字体。

文字与语音现在都能显化表达：输入时有轻微即时脉动，完整表达后由百炼转译为疏散、流动、冷暖、开放、张力、连贯、轻重和明暗八项作品参数。默认雕塑连续改变轮廓/折叠/分离与位置，照片保持主体、主要调整光感/疏散/运动。对话在侧边，1000px 内上下分区，作品和输入同时可见；这里不是心理测量，是否贴合感受仍由本人体验。

点输入条右侧麦克风 → 允许麦克风，接通后直接说，说完稍停即收到声音回复；完整转写会另用现有文字模型显化作品（最近 5 句、最多约 8000 字，单次额外调用）。音量只提供即时反馈，内容决定作品变化。插话或点「打断」清空旧声音并取消待完成的显影；结束、关闭、切换、凝结、返回或离开也取消旧结果。显影失败保留现有作品，可单独重试，不结束语音。每次语音最长 5 分钟，不保存录音；文字/语音对话历史各自独立，作品状态可延续。使用本机地址或 HTTPS，静态预览不包含后端。

### 质感试验页（对照参考视频）

开发服务启动后，在实际本地地址后加 `/relief-lab`，例如 `http://127.0.0.1:5173/relief-lab`。打开即显示一张程序绘制的虚构夜景；点「换一张照片」可换成本地照片（只在本机处理，不上传、不保存）。鼠标移到画面上会把粒子推开成一个小黑洞，孔沿堆成亮环，触屏按住拖动；离开后慢慢合上。右上 TUNE 可调密度、颗粒大小、浮雕厚度、边缘散开、孔的大小和合上速度。这是独立的画面试验，不接 AI，也不影响暗房和回廊。

### 四种形态试样（先看结构）

开发服务启动后，在实际本地地址后加 `/shape-studies`，例如 `http://127.0.0.1:5174/shape-studies`。该独立对照页展示交织丝线、层叠垂落体、舒展带状体、分离粒子群。四件使用相同银蓝颜色、每件 22,000 点、相同粒子外观分布及相机/转角，不按各自边界单独放大。

默认静态；「同步转动」让四件使用同一个转角，「还原视角」停止并回到初始角度。可逐件放大，缩小、返回四件对照或 Esc 返回。页面不调用模型、不使用麦克风、不写入回廊。用户确认结构区分度后再安排文字/语音接入；这批试样并未替换主暗房的形态或旧存档算法。

### 凝结与本地回廊

1. 点击输入条下方的「凝结此刻」。正在进行的回复/收音会结束，画面短暂失焦后定格，作品固定当前色彩、形态参数和环境相位，仍可拨动、归位；不保存临时手势和速度。
2. 名称可在保存前修改，最多 40 字；凝结卡片上有三个圆钮：「留下它」才写入本机 IndexedDB，「继续表达」回到输入，「让它散去」见第 4 条。保存完成前禁止重复写入/切换，失败保留当前作品可重试，不误报成功。保存后如继续表达，后续凝结生成新作品，不覆盖旧作。
3. 点击 GALLERY 进入横向轮播（箭头、圆点或左右方向键切换，最新的在前），点当前作品或「打开」恢复可互动场景。新保存的预览为 480×330，旧作仍用原 320×220 预览。新照片作品（v3）保存一张缩小重编码的照片（最长边 768，即发送给 AI 的同一份缩略图），打开时重新显影，并可直接继续看图对话；旧照片作品（v1/v2）仍用当时保存的粒子属性和旧画法打开；雕塑用固定种子/相位。保存作品参数、版本和 JPEG 预览，不保存原文件、聊天或录音。
4. 「让它散去」结束当前画面并回到暗房，不自动保存，也不改变已存作品。回廊「移除」可在「已移除」中恢复，没有不可撤销的清空按钮。

本地回廊只属于同一浏览器、同一站点地址（含端口）。`127.0.0.1`、`localhost`、不同端口或未来线上域名的存档各自独立；清除站点数据会丢失，当前不跨设备同步、未实现导出/迁移。移除是可恢复标记，不立即释放空间。已恢复照片的原图/上传附件未保留，如继续创作并需要 AI 看图，需重新投一张照片。浏览器不允许存储、配额不足或数据版本不支持时显示说明，原存档不被覆盖。

## 每次开发的固定节奏

1. 开始：运行 `git status`，查看 DEV_LOG 中当前任务。
2. 开发：只完成一个小目标，运行并亲自验收。
3. 记录：补充实际结果、遇到的问题与下一步；不替本人编造“已理解”。
4. 保存：查看差异，选择文件，创建本地提交，再推送。

以一次文档更新为例：

```powershell
git status
git diff
git add README.md docs/ AGENTS.md .gitignore
git diff --cached
git commit -m "docs: update development notes"
git push
```

代码任务应把本次相关代码文件也加入 `git add`。若提示没有可提交内容，无需创建空提交。

保存文件只改变本地文件；`commit` 创建本地版本；`push` 才上传已提交版本。建议每个可验收任务提交一次，开发结束前推送；当前不配置自动提交或定时推送。刷新 GitHub 提交页，确认最新提交与本地 `git log -1 --oneline` 一致。

只有自己在这一台电脑工作时，不必每次机械地拉取；若从其他设备或网页修改过仓库，先确认工作区干净，再 `git pull --ff-only`。若报错，先查看原因，不强制推送。
